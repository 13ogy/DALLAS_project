\begin{abstract}
We've developed a reproducible pipeline to forecast electricity consumption and quantify temperature-related vulnerability groups. The pipeline builds a weather-aligned hourly dataset, creates time features, trains and validates tree-based models with time-aware splits, and computes temperature elasticity to segment buildings by weather sensitivity. The final artifacts include trained models, metrics, explainability plots and the report itself.
\end{abstract}

\section{Problem Definition and Scope}

\subsection{Problem Definition}
We tend to  predict next-hour electricity usage at the building level and quantify each building's sensitivity to temperature.

\subsection{Scope definition}
The study focuses on hourly data across multiple regions. To preserve interpretability in temperature-related analyses, only hours with aligned weather observations were retained. Data sources are selected for consistent schemas and clear time semantics. Our scope is grounded in the following potential use cases:
\begin{itemize}[leftmargin=*]
  \item \textbf{Operational planning}: Next-hour forecasts and peak management.
  \item \textbf{Targeted interventions}: High-sensitivity buildings for demand response.
\end{itemize}

\section{Data Acquisition and Dataset Characteristics}

\subsection{Data Source and Collection Methodology}
We combined two large public sources (Australia's Ausgrid NSW and British London LCL) and standardized them to hourly alignment, merging per-region weather (apparent temperature, precipitation, day/night). We retained only rows with weather present to avoid exogenous imputations. Identifiers are anonymized. The unified dataset serves as the single source for feature engineering and chronological evaluation.

In practice, we first surveyed public archives and APIs for smart-meter usage data across regions. Where APIs were unavailable, we used compliant scraping to collect candidate datasets and validated schemas for usage fields and time resolution. Several sources were excluded due to missing usage fields or incompatible granularities. Weather and holiday signals were integrated per region: hourly apparent temperature, precipitation, and day/night flags. Public holidays were derived programmatically (from AU NSW region and GB calendars). We kept only rows with weather present to avoid imputing exogenous drivers, preserving integrity for temperature-sensitivity analyses.

\subsection{Web Scraping for Weather Data}
Multiple weather stations lacked API access, requiring automated scraping with BeautifulSoup4. Target sources include weather station APIs and public archives for NSW and London region. Validation included schema checks before storage, verifying temperature ranges and null value patterns.

\subsection{Technical Challenges and Solutions}
\begin{itemize}[leftmargin=*]
  \item \textbf{Schemas}: Usage data from different sources (CSV vs.\ Parquet) were normalized into a common long format (building-hour rows) to ensure consistent downstream processing.
  \item \textbf{Weather alignment}: Usage records were aligned to hourly weather data using strict inner joins.
  \item \textbf{Leakage control}: Lagged and rolling features were computed per building using shift operations, and all evaluations relied on chronological splits to prevent look-ahead bias.
  \item \textbf{Scale and performance}: Due to dataset size, chunked reads and representative sampling were used for EDA, and figures and tables were generated in compact forms.
\end{itemize}

\subsection{Data Quality: Missing Values and Outliers}

After inner-joining usage data with hourly weather observations, the modeling dataset contains 74.5M rows with complete coverage across all features. The strict alignment requirement removed approximately 25\% of original usage records that lacked corresponding weather data.

\textbf{Outlier Detection:}
We applied the IQR method ($Q1 - 1.5 \times \text{IQR}$, $Q3 + 1.5 \times \text{IQR}$) to identify extreme usage values. Approximately 0.3\% of observations were flagged as potential outliers.

\textbf{Treatment Decision:}
We retained moderate outliers (within 3$\sigma$) to preserve model robustness. Extreme outliers ($>5\sigma$, clearly erroneous) were removed (N$<$1000 rows), representing $<0.01\%$ of the dataset.

\subsection{Feature Relationships and Dimensionality}

\textbf{PCA Analysis:}
Principal component analysis on numeric features validates that engineered features capture orthogonal aspects of electricity demand. The first three principal components explain 78\% of cumulative variance, with interpretable structure:
\begin{itemize}[leftmargin=*]
  \item \textbf{PC1 (42\% variance):} Daily usage patterns (hour, lag\_1h, lag\_24h)
  \item \textbf{PC2 (24\% variance):} Weather effects (temp\_z, is\_day)
  \item \textbf{PC3 (12\% variance):} Weekly patterns (day\_of\_week, is\_weekend)
\end{itemize}

This separation confirms that calendar, temporal, and weather features provide complementary information. Despite high explained variance by the first three PCs, we retained all original features for modeling. Tree-based models handle correlated features naturally.

\subsection{Building Segmentation via K-Means}

\textbf{Clustering Methodology:}
K-means clustering (k=4) was applied to normalized hourly usage profiles (24-hour average patterns per building). Four distinct operational profiles emerged:
\begin{itemize}[leftmargin=*]
  \item \textbf{Cluster 1 (21\%, n$\approx$805):} Residential pattern---low baseline, evening peak (6-10pm), weekend similarity
  \item \textbf{Cluster 2 (31\%, n$\approx$1,190):} Commercial pattern---steep morning ramp (7-9am), 9-5 plateau, sharp evening drop, significant weekend reduction
  \item \textbf{Cluster 3 (13\%, n$\approx$500):} Industrial pattern---flat 24/7 load, minimal diurnal variation, no weekend effect
  \item \textbf{Cluster 4 (35\%, n$\approx$1,340):} Mixed-use pattern---moderate daily variation, intermediate weekend effect
\end{itemize}

\textbf{Link to Vulnerability:}
Cluster membership strongly correlates with temperature elasticity (ANOVA p$<$0.001). High-elasticity buildings (Table 4) concentrate in Cluster 2 (considered commercial), validating that HVAC-driven loads exhibit the strongest temperature response. Conversely, Cluster 3 (probably industrial) dominates low-elasticity buildings (Table 5), consistent with process loads that are insensitive to outdoor temperature.

\textbf{Modeling Decision:}
While clusters reveal heterogeneous profiles, we proceeded with a single global model that includes building\_id as a categorical feature.

\section{Experimental Design and Splits}

We employ chronological train/validation/test splits that mirror deployment conditions. Data is split based on timestamps to prevent temporal leakage: training data ends at 2014-01-26 09:00:00, validation data ends at 2017-06-19 22:00:00, and test data comprises all subsequent observations. This ensures that the model never sees future data during training or hyperparameter tuning.

Random splits were deliberately avoided, as they would lead to overly optimistic performance estimates. MAE is used as the primary metric to capture typical error magnitude, while RMSE highlights sensitivity to larger deviations.

\section{Model Development, Training, and Evaluation}

\subsection{Feature Selection, Preprocessing, and Initial Analysis}

We curated features that reflect operational reality and avoid leakage: per-building lag\_1h and lag\_24h capture persistence and daily cycle; lag\_168h captures weekly patterns; rollmean\_24h summarizes recent regime. Calendar features (hour, day\_of\_week, month, season, is\_weekend, is\_holiday) anchor seasonality and hour-level structure. Weather features (temp\_z with lagged variants, precipitation, is\_day) act as exogenous drivers. Preprocessing is minimal by design---tree-based models are scale-robust---focusing effort on correct time alignment and chronological splits.

\subsection{Baselines and Primary Model}

We compare three baseline approaches against tree-based models:
\begin{itemize}[leftmargin=*]
  \item \textbf{Naive:} $\hat{y}(t) = y(t-1)$ (persistence forecast)
  \item \textbf{Seasonal-24:} $\hat{y}(t) = y(t-24)$ (same hour yesterday)
  \item \textbf{Weekly-168:} $\hat{y}(t) = y(t-168)$ (same hour last week)
  \item \textbf{RandomForestRegressor:} Stable ensemble baseline
  \item \textbf{HistGradientBoostingRegressor:} Primary model
\end{itemize}

Training uses large sampled subsets per split to bound memory while preserving time ordering. Hyperparameters were selected based on validation performance, prioritizing generalization over training fit.

\section{Key Findings}

The resulted next-hour forecasting accuracy is compared to naive baselines. Gradient boosting reduces MAE and RMSE on both validation and test periods. Temperature and recent usage dynamics emerge as dominant predictors in feature importance analysis. Building-level elasticity reveals wide variation in temperature response across buildings, with commercial buildings showing 7$\times$ higher sensitivity than industrial loads. Errors concentrate during morning and evening transition hours where regime changes.

\textbf{Performance in Context:}
To assess model performance relative to baseline difficulty, we compute skill scores that measure proportional improvement over naive forecasts:
\begin{itemize}[leftmargin=*]
  \item \textbf{Skill Score (Naive):} $1 - (\text{MAE}_{\text{model}} / \text{MAE}_{\text{naive}}) = 1 - (0.0242/0.0397) = $ \textbf{39\% improvement} over persistence
  \item \textbf{Skill Score (Seasonal-24):} $1 - (0.0242/0.0430) = $ \textbf{44\% improvement} over same-hour-yesterday forecast
  \item \textbf{RMSE/$\sigma$:} $0.0340 / \text{std}(y_{\text{test}}) \approx 0.34$ (model error is 34\% of target standard deviation)
\end{itemize}

These metrics show strong performance for a one-hour horizon. The 39\% improvement over naive persistence is substantial given that electricity demand exhibits high autocorrelation, making persistence a strong baseline. The gap between HistGBR and RandomForest (0.0242 vs 0.0270 MAE) is modest but consistent, justifying the choice of gradient boosting.

\textbf{Model Comparison Analysis:}

Comparing across model families reveals distinct performance patterns. The naive baseline (MAE = 0.0397) establishes that simple persistence is already quite strong given electricity demand's high autocorrelation. Seasonal baselines (Seasonal-24 and Weekly-168) surprisingly perform worse than naive (MAE = 0.0430 and 0.0541 respectively), indicating that hour-to-hour persistence is a stronger signal than same-hour-yesterday or same-hour-last-week patterns in this dataset.

Tree-based models substantially outperform all baselines. RandomForest achieves 32\% improvement over naive (0.0270 vs 0.0397), demonstrating the value of combining multiple features beyond simple persistence. HistGradientBoosting achieves an additional 10\% relative improvement over RandomForest (0.0242 vs 0.0270), justifying the added complexity through sequential error correction and feature interaction modeling.

The consistency between validation and test performance (HistGBR: 0.0206 val vs 0.0242 test) indicates good generalization without overfitting. The 17\% increase in test error relative to validation reflects the challenges of forecasting further into the future.

\section{Model Interpretability via Permutation Importance and PDP/ICE}

\subsection{Method}

We estimate per-building temperature elasticity by varying temp\_z on a fixed grid [-3, 3] (approximately 6 standard deviations) for sampled hours in the test period, predicting with the trained model, and fitting a linear slope dy/dtemp to the resulting ICE curve. The elasticity for each building is defined as the median slope across sampled hours, which reduces sensitivity to outliers and provides a robust summary of typical temperature response. Elasticity represents model-implied temperature sensitivity and is not interpreted as a causal effect.

\section{Discussion}

\subsection{Interpretation of Key Results}

The HistGradientBoosting model achieves 39\% improvement over naive persistence by exploiting temporal autocorrelation and usual usage patterns. Both permutation importance and SHAP analysis confirm that lag\_1h dominates predictions, reflecting strong hour-to-hour persistence in building operations.

Building-level elasticity shows that commercial buildings exhibiting 7$\times$ higher sensitivity than industrial loads. This heterogeneity aligns with clustering results helping to create clear weather vulnerability profiles.

Errors concentrate during mornings and evenings transition periods where our short-horizon features struggle to anticipate regime shifts between overnight.

\subsection{Limitations and Potential Biases}

\textbf{Data Filtering Bias:} Strict inner-join filtering removed 25\% of original observations lacking weather data. This filtering may bias findings toward buildings in well-monitored regions with reliable weather station coverage, potentially underrepresenting rural or poorly instrumented areas.

\textbf{Normalization Trade-offs:} Per-building normalization enables cross-building behavioral comparison but prevents absolute load forecasts. Grid operators requiring total MW predictions would need building-specific denormalization factors, introducing additional uncertainty.

\textbf{Temporal Distribution Shift:} Data spans 2007-2022, predating recent technology adoption (rooftop solar, smart thermostats, electric vehicles, heat pumps) that may have fundamentally altered consumption patterns and temperature responses.

\textbf{Single Global Model Limitations:} A unified model across four distinct building clusters may have underfitted heterogeneous operational patterns.

\section{Conclusion}

We have successfully developed a production-ready pipeline for next-hour electricity forecasting and temperature vulnerability profiling across 3,835 buildings spanning 74.5 million hourly observations. The pipeline demonstrates that rigorous time-series methodology can produce operationally deployable systems balancing accuracy with explainability. HistGradientBoosting achieved 39\% improvement over naive persistence through temporal persistence features (lag\_1h, lag\_24h). Temperature elasticity analysis revealed variation in weather sensitivity, enabling targeted identification of vulnerable infrastructure.
